2D top-down экшен про самурая (мобильный в первую очередь): игрок бросает отскакивающий нож, враги ходят по A\*, есть
парирование, здоровье, экран смерти, уровни с ключом и дверью. Соло-разработка, **живьём через Unity MCP** в открытом
редакторе. Личность и тон ассистента («Петька») — в `C:\Users\Admin\CLAUDE.md`, здесь только про проект.

## Соглашения кода

- «Перед» спрайта = **+Y при повороте 0**: везде `Mathf.Atan2(dy, dx) * Rad2Deg - 90f`.
- Враги — **Kinematic** `Rigidbody2D`. Позицией владеет AIPath: `transform.position` он затирает. Телепорт — `ai.Teleport`,
  мелкие подталкивания — **`ai.Move`** (Teleport каждый кадр обнуляет скорость).
- Визуал врага — дочерний `Visual` + `VisualRotationSmoother`; корень вращает AIPath.
- Проверка пролёта снаряда: `CircleCast` с реальным радиусом внутри `Physics2D.queriesStartInColliders = false` (с
  возвратом), не `Linecast`/`Raycast` нулевой ширины.
- UI, строящийся в коде (`ParrySystem`, `DeathScreen`, `PlayerHealthBar`, `LevelManager`, `GameSpeedButtons`): legacy `Text`
  + `LegacyRuntime.ttf`. Готовые TMP-надписи (счётчики попаданий) русский рисуют через динамический запасной шрифт.
- Публичные поля настроек, `[Tooltip]` по-русски. Новое поле на уже сериализованном объекте получает дефолт из кода один
  раз; дальше значение живёт в сцене (меняя дефолт в коде, поправить и сцену).
- Один MonoBehaviour — один файл с тем же именем. `using System;` рядом с `UnityEngine` даёт неоднозначный `Random`.
- Статические счётчики (`Kunai.TotalHits` и т.п.) переживают перезапуск сцены — обнулять на старте уровня.

- `ai.canMove` / `ai.isStopped` пишут: `EnemyChaseStop` (остановка по касанию игрока, не для дальнобойных), `EnemyAttackZone`
  (стоит на замахе), `AntiTricker` (рывок), `KunaiFighter`/`ArcherFighter` (каждый кадр), `EnemyDeath`, `CombatAgent` (гонец,
  отступ без токена). Явные хэнд-оффы: `IsWindingUp`, `IsCountering`, `IsWithdrawing`, `IsCalling`, `IsReserve`. Не ставить
  `canMove = true` насильно.
- `Time.timeScale` пишут `TestScript` (замедление при прицеливании), `ParrySystem` (0), `StartFreeze` (0 до первого действия),
  `PlayerHealth` (0 при смерти), `DeathScreen`, `GameSpeed.Set` (кнопки 0.5/0.75/1). Все домножают на `GameSpeed.Multiplier`;
  новый код проверяет `ParrySystem.Active` / `PlayerHealth.IsDead` / `StartFreeze.Waiting`.
- Цель `AIDestinationSetter` у мечника: игрок (есть токен), точка ожидания/флангового слота, либо дремлющий (гонец).

## Архитектура боя (кратко; подробности и числа — PROGRESS.md)

- **Мечник** (`EnemyAttackZone`): замах 0.1 с, удар засчитывается, если игрок остался в зоне (в конце замаха радиус +0.5).
  Правило «**дотянулся — бьёт**»: ближнего бойца директор не блокирует никогда (ни токен, ни пауза, ни резерв).
- **Парирование** (`ParrySystem`): включается только когда урон реально проходит и игрок смотрит на врага (конус 120°); общее
  на нескольких одновременно ударивших мечников (шарик быстрее ×1.5 за каждого); квадратик в случайном месте; кулдаун 5 с.
  Поворот игрока на телефоне: во время прицеливания — к прицелу, после броска — обратно по направлению движения.
- **Координация** (`CombatDirector` + `CombatAgent` на префабах врагов; нет директора → враги ведут себя как раньше):
  кольца Melee/Mid/Far, токены на выстрел/«в бой», общая пауза и справедливая очередь для стрелков; у мечников один токен и
  ранги маршрутов (0 главный, 1 второй…) — при гибели все сдвигаются в тот же кадр; ждущие идут в слоты на разных сторонах
  игрока (фланги), стрелки штрафуют точки на одной стороне с другими. Группа ≤ `maxGroupSize`, остальные **дремлют**
  (`startDormant`, `activationRadius`); недостающих окликает гонец группы — наименее опасный: кунайщик → лучник → мечник.
  Зон ответственности (кто кого может звать) **пока нет** — будущая задача.
- Смерть врага: `EnemyDeath` выключает все его скрипты, роняет оружие, шлёт `Died`; `LevelManager` по последнему убитому
  роняет ключ → дверь `ExitDoor` → следующая сцена или «Игра пройдена».
- Враги расталкиваются (`EnemySeparation`, в рывке AntiTricker не работает).

## Unity MCP — как работать

- `Unity_RunCommand` (параметры называются `Code` и `Title`, проверяй схему): `internal class CommandScript : IRunCommand`,
  `Execute(ExecutionResult result)`, `result.Log`. Нет `System.Reflection`. Скрипт компилируется в отдельной сборке: **internal-
  поля игры ему недоступны**, нужны публичные. Неоднозначность `Image` → `UnityEngine.UI.Image`.
- Real-time `Update` между вызовами не идёт → симуляция циклом **`EditorApplication.Step()`** (dt 0.02). Корутины на
  `WaitForSecondsRealtime` в Step не тикают (реальное время почти не идёт) — проверять следующим вызовом после паузы.
- Play: `EditorApplication.isPlaying = true`, ждать ~9 с. **Не править скрипты во время Play** (домен-релоад убивает граф A\*).
  Остановить Play → править → `AssetDatabase.Refresh()` (файлы, созданные вне редактора, иначе не видны) → ждать компиляцию
  (~20 с, `isCompiling`) → Play. Если после Refresh типы «не существуют» — смотреть ошибки компиляции в консоли.
- В Bash `sleep` с большими значениями блокируется: держаться ≤ 20 с на вызов.
- Правки кода Python-скриптом: файл через Write c `# -*- coding: utf-8 -*-` и запуск с `PYTHONIOENCODING=utf-8` (кириллица в stdin
  ломается). Всегда `assert count == 1` перед заменой.
- Поля инстансов префабов в сцене: `PrefabUtility.RecordPrefabInstancePropertyModifications` + `MarkSceneDirty` + `SaveOpenScenes`;
  значения префаба — `LoadPrefabContents`/`SaveAsPrefabAsset`. `GameObject.Find` не видит неактивные объекты.
- **Граф A\* в редакторе:** после правки `GridGraph` — `d.SetData(d.SerializeGraphs())` (один `SerializeGraphs()` не сохраняет);
  копия сцены наследует старую сетку; для новых уровней — меню «Подогнать уровень» (`LevelTools.FitLevel`). `Collider2D.bounds`
  вне Play бывают пустыми — считать по геометрии.
- **Рецепт симуляции** (чтобы тест был чистым): `StartFreeze` выключить, `Time.timeScale = 1`, `TestScript` выключить (иначе
  поворот уходит за мышью), `Rigidbody2D` игрока → Kinematic (иначе снаряды его сносят), `ParrySystem.Instance.player = null`
  (если парирование мешает), `ai.Teleport` для расстановки врагов, метрики числами (расстояния, счётчики, кадры). Для тапа
  парирования — `ParrySystem.Tap()`; ввод Input System из MCP не проходит (окно без фокуса). Временных врагов/объекты
  удалять и сцену сохранять в исходном виде.
- Классификатор разрешений иногда падает («no verdict») — повторить вызов.
